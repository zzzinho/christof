# Christof UX

앱과 위젯의 흐름·상태·문구에 대해 정한 것과 그 이유를 적는다. 위젯 장면(그림)은 `design/DESIGN.md` 가 다룬다.

- 동작 문장의 원본은 설명서(`swift test --package-path ChristofKit --filter <Suite>` 출력)다. 여기에는 무엇을 왜 정했는지와 그 Suite 이름만 적고, 테스트 문장을 옮겨 적지 않는다.
- 개발 세션이 고치고, 디자인 세션은 읽기만 한다.

## 원칙

1. 알아낼 수 있는 것은 묻지 않는다. 지역·시각·날씨·이벤트의 기본은 "자동"이다.
2. 실패를 기본값으로 덮지 않는다. 기본값(위치는 마지막에 고른 지역이나 부산, 날씨는 맑음)을 쓰더라도 화면에 이유를 보이고 `Logger` 로 남겨 성공과 구별되게 한다. 응답이 오지 않을 수 있는 요청에는 시한을 둔다.
3. 상태는 그 항목 곁에 문구로 보인다. 알림 창은 띄우지 않는다.

## 화면과 상태

앱은 설정 화면 하나다. 설명서가 "—"인 상태는 판단이 화면 코드에 있거나 판단이 없다.

## 문구

- 화면 문구는 영어 원문과 한국어 번역을 `Localizable.xcstrings` 에 둔다.
- 용어: Save 저장, Applied/Apply 적용, Auto 자동, Region 지역, Design 디자인, Time 시각, Event 이벤트, Edit Widget 위젯 편집, Update 업데이트, Real forecast 실제 예보.
- 실패 문구는 무엇이 안 됐는지, 대신 무엇을 쓰는지, 사용자가 할 수 있는 일(있으면)을 쓴다. 예: "Location access is off, so Auto uses Seoul. Allow location access for Christof in Settings."
